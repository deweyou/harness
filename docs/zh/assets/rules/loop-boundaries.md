# 循环边界

迭代实现、调试、测试修复、视觉打磨、CI 跟进和长时间开发工作中使用本 Rule。

## 继续的条件

- 下一步行动可以从证据中明确得出。
- 改动仍在当前范围内。
- 验证失败指向一个具体且可能有效的修复。
- 用户已经授权这一类操作，例如本地代码修改或低风险 CI 修复。

## 停止或询问的条件

- 多次尝试因为同一个不明确原因失败。
- 存在多种合理修复，并且会改变产品行为、API、数据、安全或用户体验。
- 下一步会删除、覆盖、发布、发送、花费或暴露数据。
- 修复会碰到无关且属于用户的未提交改动。
- 验证无法证明准备宣称的结论。

## 交接

停止时，报告当前循环状态：

- 尝试过什么
- 收集了什么证据
- 当前阻塞是什么
- 需要用户做出的具体决策

## DDev Graph 记录

对于多步骤 DDev session，维护轻量 `graph.md`，不要只依赖对话记忆：

- 列出当前步骤或依赖边。
- 标明每一步是进行中、完成、阻塞还是延期。
- 失败后记录需要重新运行的最小影响范围。
- 重试记录保持简短，并由证据支持。

重试预算耗尽后，不要重复运行同一步。重新分类问题、拆分步骤、返回上下文或设计阶段；
当下一步会改变产品或业务方向时，询问用户。
