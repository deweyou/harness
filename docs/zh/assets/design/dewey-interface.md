# Dewey 界面设计

本文档是 Dewey 个人界面风格的设计事实源阅读版，供人类和 AI Agent 在做产品 UI
决策前阅读。

`DESIGN.md` 更接近项目级设计契约，而不是工作流。它应与 UI/UX Skill 配合使用：
Skill 决定要做什么工作，本文档决定界面应呈现怎样的感觉、文案和组合方式。

## 设计主张

Dewey 的界面风格克制、重排版、组件驱动且强调功能。它应该像一个小而精心制作的
产品系统，而不是通用 SaaS 模板。

核心判断语句：

> 简洁、干净、线条利落。少即是多。

## 原则

- 先解决可用性，再考虑风格。个人品味不能凌驾于清晰度、无障碍、可恢复性或平台惯例。
- 用结构代替装饰：通过层级、字体、间距、边框和状态承载界面。
- 让颜色具有语义。中性色负责组织产品，祖母绿表示主要强调，红色只表示危险，
  琥珀色只用于反馈。
- 保持平静的密度。工具和仪表盘应紧凑且容易扫读；营销页面可以更宽松，但不能变得装饰化。
- 尊重平台惯例。Web、H5、iOS、Android、HarmonyOS、小程序和 macOS 可以共享品味，
  但不应强行共享完全相同的控件或导航。
- 行为实现优先使用可访问的原生或 headless primitives，不要手写 focus、键盘和 ARIA 逻辑。

## 字体排版

- 控件、密集 UI、导航、标签、表单和操作界面使用思源黑体。
- 内容、Markdown、长文、编辑层级和展示性场景使用思源宋体。
- 不要到处使用衬线字体；控件应保持清晰利落的无衬线风格。
- 只使用 400、500、600 和 700 字重。
- 展示性字体只用于真正的展示场景。紧凑面板、卡片、侧栏和控件需要更小、更紧的标题。
- 避免负字距。小号全大写标签只在确有帮助时使用适度正字距。

## 颜色

- 组件中使用语义 token，不直接写原始颜色。
- Neutral / stone：文字、边框、表面和中性操作。
- Primary / emerald：选中状态、focus、主要操作和品牌强调。
- Danger / red：破坏性操作和错误。
- Warning / amber：警告 toast 等临时反馈，不作为通用组件颜色。
- Logo 或品牌标志可以使用渐变；产品表面不要使用装饰性渐变。
- 功能色不能是传达含义的唯一方式。需要时为错误、警告、成功和选中状态配合标签、
  图标或形状。

## 表面、布局与密度

- Canvas：浅色模式使用中性浅灰；深色模式使用低眩光 stone 色。
- Surface：白色或抬升层 token 表面，优先使用边框分隔。
- Card：1px 边框、surface 背景，默认无阴影。
- Floating layer：dialog、popover、menu 和 toast 可以使用阴影与抬升表面。
- 间距遵循 4px 节奏，并使用既定的 `xs`、`sm`、`md`、`lg` 和 `xl` 层级。
- 圆角只使用既有层级：`rect`、`float`、`auto` 和 `pill`。
- 避免嵌套卡片和装饰性 section 容器。
- 为控件、工具栏、网格、tab、tile 和计数器预留稳定尺寸，避免动态内容导致布局跳动。

## 交互

- 移动端触控目标至少为 44px。
- Focus 必须可见。
- Hover 不能是唯一的可操作提示。
- 按压反馈应迅速，且不能推动周围布局。
- Loading 应禁用重复操作、保持布局宽度，并在有用时展示进度或 skeleton。
- Disabled 控件不能看起来仍可点击。
- 错误应在受影响区域附近解释原因和恢复方式。
- 空状态应解释缺少什么，并提供下一个有用操作。
- 破坏性操作应在视觉上隔离，并在风险实质存在时要求确认。
- 动效使用 140–300ms，体现因果关系，尽量只改变 transform/opacity，并尊重 reduced motion。

## 图标

- 项目已有图标系统时使用项目系统。
- 偏好 Tabler 风格的描边 SVG 图标：1.5 stroke、square linecap、miter linejoin。
- 对容易识别的工具和紧凑操作使用图标。
- 纯图标控件必须具有无障碍名称。
- 不要把 emoji 当作结构性 UI 图标。
- 保持图标家族、描边、尺寸和对齐一致。

## 文案

除非产品上下文需要其他语言，面向用户的文案通常应使用简洁英文。保持事实性和紧凑。

- 使用清晰的名词和动作动词。
- 避免夸张宣传、口号、过度承诺和感叹号。
- 符合产品语言时，使用 `·` 作为 metadata、eyebrow 和并列标签的默认分隔符。
- 按钮直接描述动作：`Save`、`Copy`、`Delete`、`Export`。
- 纯图标控件的无障碍名称应描述动作：`Open menu`、`Open more actions`、
  `Close dialog`。

## 应该做

- 从用户真实工作流和信息层级出发。
- 使用中性表面、边框优先的分隔、紧凑层级和语义颜色。
- 覆盖空、加载、错误、成功、禁用、选中、focus 和破坏性状态。
- 把浅色和深色主题作为一组来设计。
- 每个页面只保留一个主要操作。

## 不应该做

- 不要把装饰性渐变、散景、玻璃拟态、通用图库氛围或奶油/米色主题作为产品主要视觉语言。
- 不要在同一产品中混用扁平、拟物、玻璃、黏土、粗野主义和新拟态等无关风格。
- 不要用 emoji 作为导航、设置或系统图标。
- 不要让仪表盘或工具看起来像营销页面。
- 存在语义 token 时，不要在组件中使用原始颜色、任意圆角或随机阴影。

## AI 设计提示词

让 AI 设计工具使用 Dewey 风格工作时，可采用下面的简短提示：

```text
使用 Dewey 当前的界面风格进行设计：克制、英文优先的产品 UI；控件使用思源黑体，内容和展示文字使用思源宋体；中性浅灰画布、白色带边框表面、深祖母绿作为主要强调色、红色只用于危险；不使用 emoji、装饰性渐变、玻璃拟态或通用图库氛围。优先保证工作流清晰、层级紧凑、触控目标可访问、安全区域正确、状态可见和动效平静。
```
